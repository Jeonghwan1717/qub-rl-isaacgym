# 보행 진단 스크립트

QUB 이족보행 정책의 좌우 대칭과 접지 자세를 정량 측정한다. 학습 로그의 리워드 값은
`raw × scale`의 시간평균이라 물리량을 역산할 수는 있지만, 명령이 0인 env가 20% 섞여
값을 희석하므로 **판정은 반드시 이 스크립트들의 직접 측정으로** 한다.

## 공통 사용법

```bash
export PATH=$HOME/miniconda3/envs/kudos/bin:$PATH
export LD_LIBRARY_PATH=$HOME/miniconda3/envs/kudos/lib:$LD_LIBRARY_PATH
export ROBOT_TYPE=QUB
cd <repo root>
python -u legged_gym/scripts/diag/<script>.py \
    --task=qub_flat --load_run=<run> --checkpoint=<n> --headless
```

모든 스크립트가 공유하는 측정 조건:

- **64 env, 도메인 랜덤화·관측 노이즈 전부 off** — 정책 자체의 성질만 본다
- **명령 속도 램프업 (0 → 목표, 100스텝)** — 정지 상태에서 목표 속도를 바로 때리면
  넘어지는 개체가 생겨 통계가 오염된다 (0.6 스윕 실측: 즉시 인가 시 생존 74%, 램프 시 100%)
- 200스텝 안정화 후 측정 시작
- 측정 전체 구간 생존한 개체만 통계에 포함

## 스크립트

| 파일 | 측정 대상 | 판정 기준 |
|---|---|---|
| `foot_flatness.py` | **발바닥이 땅에 평평하게 닿는가** (월드 기준). 발 좌표계에서 본 중력의 x/y 성분 | 스탠스 중 tilt가 0에 가까울수록 발바닥 전체 접지 |
| `joint_sym_check.py` | 다리 6관절쌍의 미러 잔차, torso_yaw DC/AC, 발 heading | 6관절 제곱합 (rad²) 및 관절별 잔차(도) |
| `step_asym.py` | 좌우 발의 골반 기준 앞뒤 위치·보폭 | 전후위치 차이(cm), 보폭 차이(%) |

## 측정 설계에서 주의할 점

**1. 기준 프레임을 틀리면 잘못된 성공을 선언하게 된다.**
`step_asym.py`가 base_link가 아니라 pelvis_link를 쓰는 이유: 다리는 pelvis에 달려 있고
그 사이에 `torso_yaw_joint`가 있다. base 기준으로 재면 골반을 비트는 것만으로 좌우
오프셋이 전후축에 섞여 수치가 좋아 보인다 (실측 은폐량 1.30 cm).

같은 이유로 `foot_flatness.py`는 **월드 기준**으로 잰다. "발바닥이 땅에 닿는가"는
월드 기준 질문인데, 골반 기준 pitch로 재면 보행 중 골반이 앞으로 기운 만큼 어긋난다.
실제로 골반 기준 pitch −1.32°(평평해 보임)인 발의 땅 기준 기울기가 9.93°였다.

**2. 관절이 아니라 말단(발)을 재야 하는 경우가 많다.**
관절각은 운동학적 잉여로 상쇄될 수 있다. 발 접지가 문제일 때 발목 관절 진폭을 봤다가
표적을 잘못 잡은 적이 있다 — 발목 진폭은 왼쪽이 작았지만 발 피치 범위는 왼쪽이 3배 컸다.

**3. 미러 부호는 URDF 축에서 유도한다.**
시상면 반사에서 각속도는 유사벡터라 `(ωx,ωy,ωz) → (−ωx,+ωy,−ωz)`, 즉 pitch는 부호
유지·roll/yaw는 반전이다. 좌우 축이 반대인 관절은 한 번 더 반전된다. QUB에서
`ankle_pitch`만 좌우 축이 반대(`R(0,−1,0)` / `L(0,+1,0)`)이므로 이 관절만 부호가 다르다.
`joint_sym_check.py` 상단의 마스크는 이 유도 결과다.

**4. DC와 AC를 나눈다.**
보행은 좌우 180° 위상차라 매 순간 좌우가 다른 것이 정상이다. 문제는 한쪽으로 치우쳐
고정된 성분(DC)이다. 순간값 비교는 양발이 함께 움직이는 제자리뛰기를 유도한다.
